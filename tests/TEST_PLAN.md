# Bug Busters Test Plan

## Scope
- Validate gameplay loop (random bug movement, scoring per click, single 20s round) and post-game messaging/reset behavior.
- Confirm issuer data panel loads `data/issuers_index.json`, groups issuers by period folder, and surfaces friendly errors when files are missing/malformed.
- Verify leaderboard wiring: refreshing data, submitting results to backend, and frontend/CLI fallbacks when `/health` or `/scores` fail.

## Test Environment
- Run backend Node server from `backend/server.js` with in-memory leaderboard plus CORS/static hosting enabled.
- Serve frontend assets from `frontend/` via the backend or a static server; ensure the app fetches `data/issuers_index.json`.
- Base URL assumptions: `http://localhost:3000` for frontend and API (adjust if configured differently).

## Data & Tools
- Issuer data pulled from `data/issuers_index.json` generated by the Data Scanner (rerun after changing `Unified_ver1/data`).
- Browser devtools for network inspection, `curl` for direct API probing, optional mocked infotable omissions to simulate malformed inputs.

## Manual checks
- GET /health response: `curl http://localhost:3000/health` should return 200 with `{ status: "ok" }` (or similar) JSON; confirm response shape matches backend contract and verify UI handles outage messaging.
- GET /scores behavior: ensure `curl http://localhost:3000/scores` returns status 200 and up to ten entries sorted (highest first if specified); confirm the frontend leaderboard fetches `/scores` successfully and renders top 10 in the correct order.
- POST /scores validation: submit a valid payload (e.g., `{ "name": "QA", "score": 42 }`) and ensure 200/201 plus leaderboard refresh; try invalid payloads (missing name, non-numeric score, >10 entries) to verify backend rejects them with meaningful errors and frontend shows validation feedback.

## Gameplay Flow Tests
1. Load the page; timer displays 20 seconds and bug starts within bounds.
2. Click the bug repeatedly; confirm scoring increments per click and bug relocates randomly while staying visible.
3. Let the timer elapse; confirm it stops at exactly 20 seconds, disables clicks, announces final score, and offers score submission/reset.
4. Restart or submit again (if supported) to ensure timers, score, and UI state reset cleanly.

## Issuer Panel & Data Resilience
1. Verify right-side panel groups issuers under each period header pulled from `data/issuers_index.json`.
2. Spot-check issuers by opening their `infotable.xml` sources to ensure grouping accuracy.
3. Temporarily rename/delete an infotable then rerun the scanner; confirm panel surfaces fallback messaging without crashes and log notes about skipped files.
4. Test behavior when `data/issuers_index.json` is unavailable or malformed, ensuring the UI notifies users gracefully.

## Leaderboard & Backend Integration
1. Finish a round and submit score; expect confirmation and leaderboard update.
2. Submit multiple scores of varying values via UI and direct POST calls to confirm top-10 clipping and ordering consistency.
3. Stop the backend to simulate downtime; UI should handle failures gracefully and retry once backend recovers.
4. Check memory-only persistence by restarting backend and ensuring scores reset.

## Documentation & Scanner Validation
1. Review `docs/project_overview.md`, `docs/task_breakdown.md`, and `docs/requirements_checklist.md` for coverage of gameplay, timers, data panel, backend routes, and storage strategy.
2. Inspect `design/ui_spec.md` and `design/wireframe.png` for layout details (game area, leaderboard, issuer panel) and styling guidance.
3. Confirm `data/scan_plan.md` enumerates folders/parsing strategy and that `data/issuers_index.json` matches runtime data usage, including malformed-file handling steps.

## Automation & CLI Checks
- Run `tests/test.sh` (curl-only script) to ensure `/health`, `/scores`, and POST `/scores` respond with success codes; integrate into CI smoke tests before releases.

## Risks & Edge Cases
- Rapid score submissions may collide with leaderboard refresh; confirm dedupe/ordering logic remains correct.
- Attempt leaderboard fetch before Data Scanner output exists; frontend must show fallback state and allow retry.
- Validate response when issuers_index omits a period or includes unexpected schema, ensuring UI warns about incomplete data.
